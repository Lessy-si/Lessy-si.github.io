USER JOURNEY & USER FLOW

从发现一首歌，到连接一个人

以完整歌曲收听为核心，让用户轻松发现音乐、推荐音乐，并通过音乐品味连接人。

用户旅程操作流程
01

用户旅程

覆盖进入、收听、参与与回访；“产品规划”表示尚需接入或完善的能力。

  1. 1

    进入并开始听

    产品规划

    “先听到符合预期的音乐。”

    用户行动
    完成注册后进入 Feed；首批内容承接渠道预期，无渠道信息时使用准备好的兜底内容。
    产品回应
    不以偏好问卷阻挡首次收听；Taste Builder 在后续合适时机邀请参与。
    体验障碍
    首批内容不合适、首次选择过多。
    观察结果
    首次有效收听、首次推荐、到达所需时间。
  2. 2

    发现喜欢的歌

    “持续听歌，也能知道是谁推荐。”

    用户行动
    在 Feed 收听、切歌，查看艺人介绍和推荐理由；需要时从 Music 换一个方向。
    产品回应
    歌曲、介绍和推荐者准确对应；切页浏览不中断音乐。
    体验障碍
    视频与歌曲错配、声音重叠、滑动误触。
    观察结果
    有效收听、主动收藏、切歌及播放失败。
  3. 3

    一键推荐

    “轻松把喜欢的音乐传给别人。”

    用户行动
    首次点击 Recommend，即完成基础推荐；也可以单独收藏歌曲。
    产品回应
    推荐状态立即可见，头像落入封面推荐位，底部反馈 Recommended；Add a note 可忽略。
    体验障碍
    把推荐误解为收藏，误以为必须录音。
    观察结果
    基础推荐成功率、撤销率、提示后的继续收听。
  4. 4

    自愿补充表达

    “想说时，再分享为什么喜欢。”

    用户行动
    选择录音或文字，试听、编辑后提交；可以取消或稍后补充。
    产品回应
    关闭附言不会取消基础推荐；重复编辑更新同一条推荐。
    体验障碍
    权限被拒、提交失败、草稿丢失。
    观察结果
    推荐者中的附言参与率、提交成功率与放弃原因。
  5. 5

    探索一个人的品味

    “找到值得持续关注的人。”

    用户行动
    点击推荐或评论头像进入主页，浏览推荐、歌单，选择关注。
    产品回应
    主页保留原有身份与内容模块，推荐融入其中；预览少量条目，More 查看完整列表。
    体验障碍
    主页内容过长，推荐失去人物上下文。
    观察结果
    主页访问、继续听其推荐、关注。
  6. 6

    获得反馈

    产品规划

    “知道自己的推荐有没有帮助别人。”

    用户行动
    查看与本人推荐有关的回复、感谢等互动；点开定位到对应推荐和回复。
    产品回应
    推荐反馈与歌曲总推荐人数分别统计，消息不跳到无关歌曲或回复。
    体验障碍
    把同曲所有评论误算为对我的回复。
    观察结果
    真实反馈送达、阅读及回访对应内容。
  7. 7

    找回与再次收听

    “随时找到自己的音乐和推荐资产。”

    用户行动
    从 Library 查看收藏、歌单、历史和本人推荐；在主页继续管理推荐。
    产品回应
    保持入口列表的顺序和来源；返回恢复位置；列表结束提供重播或继续发现。
    体验障碍
    静默切换到发现流，返回丢失位置。
    观察结果
    找回成功、回听、来源一致性及再次推荐。
  8. 8

    持续使用与权益选择

    产品规划

    “愿意回来，并理解可选择的收听权益。”

    用户行动
    通过相关互动和新作品回来；需要时选择广告解锁或付费权益。
    产品回应
    权益先说明再确认；付费和广告失败均有恢复路径。下载与离线方案定稿后开放。
    体验障碍
    无关提醒、权益不清、付出后未获得权益。
    观察结果
    反馈后回访、持续收听、权益完成及失败恢复。
02

核心操作流程

首次收听

  1. 进入 / 注册
  2. 进入 Feed
  3. 收听与切歌
  4. 收藏或一键推荐
  • 有有效渠道信息：匹配首批内容；没有：使用兜底内容。
  • 未命中兴趣：继续发现或进入 Music；Taste Builder 的邀请时机属于产品规划。

推荐与附言

  1. 未推荐
  2. 点击 Recommend
  3. 基础推荐成功
  4. 继续听歌 / Add a note
  • 添加附言：录音或文字 → 试听 / 编辑 → 提交 → 更新同一条推荐。
  • 取消附言：保留基础推荐；再次点击已推荐入口：编辑或进入二级撤销确认。
  • 保存失败：保留草稿，明确失败；不增加推荐数，不播放成功动效。

人物与回访

  1. 推荐者 / 评论头像
  2. 个人主页
  3. 推荐预览 / More
  4. 继续探索 / 关注
  • 当前可体验主页浏览、关注状态和推荐列表；返回恢复原入口与位置。
  • 产品规划：推荐条目进入保留人物与附言的 Feed 式内容页，沿当前人物列表浏览。
  • 产品规划：相关互动 → 消息 → 对应推荐 / 回复；失效内容说明原因并可返回。

回听与队列

  1. 收藏 / 本人推荐 / 歌单
  2. 选择歌曲
  3. 沿来源列表播放
  4. 列表结束
  • Replay list：从该列表重新开始；Continue discovering：用户主动转入发现流。
  • 浏览其他页面不换歌；明确点播新内容才接管播放；上下首始终服从当前队列。

01

产品定位与目标

英国版本沿用 Boomplay 既有音乐能力与非洲版视觉组件，以 Feed 承接音乐发现和轻量的人际推荐。

  • 面向希望发现新音乐、找回喜欢的歌，以及愿意通过音乐表达品味的英国听众；不以族裔推断个人兴趣。
  • 核心价值：先听到音乐，一次点击即可推荐，愿意时再补充表达；推荐能被找回，并逐步获得有归属的反馈。
  • 优先验证首次有效收听、首日基础推荐和推荐后的回访。附言是深度参与，不能成为基础推荐的门槛。
  • 产品目标面向完整英国业务。原型用于验证流程与理解，素材数量、预置互动和界面完成度不等于需求、留存或商业成立。

信息架构：三个 Tab 与共用页面

页面用户任务主要承接
Music主动探索与换方向主题 / 场景 / 曲风入口、搜索、歌单与点播。一期沿用原有列表及播放器。
Feed（默认）持续发现音乐和人完整歌曲、关联艺人介绍、推荐者与附言、收藏、推荐、互动。

消息（规划）查看与自己有关的反馈一级互动列表、二级私信；官方消息与音乐互动分开承接。
共用播放能力浏览时继续听，明确选择时换歌单一音频会话、全屏播放器、统一底部播放栏和播放队列。
04

FR01 · 首次进入与兴趣建立

产品规划
  • 正式产品在注册后进入 Feed，优先让用户听到内容；登录方式、授权范围、游客权限及账号迁移规则需单独确认。
  • 首批内容与有效渠道预期衔接；无渠道线索采用兜底内容。不能仅凭一次滑走判定用户不喜欢该类型。
  • Taste Builder 后置且可退出；触发条件、兴趣选择方式和所需样本量通过实际内容验证，不把示例数量写成强制任务。
  • 加载、无内容、播放失败分别反馈；重试不得起播错误歌曲。正式原生后台能力与 Web 展示能力分别验收。
05

FR02 / FR07 · Feed 与内容衔接

  • 以完整歌曲为消费单位，呈现封面、歌名、艺人、播放进度与操作。艺人介绍用于连接具体作品，不把循环背景、介绍、MV 与 Clips 混为一类。
  • 介绍结束或跳过介绍时进入匹配歌曲；无匹配歌曲的介绍不能进入空音频状态。视频失败时提供有效回退，不播放无关作品。
  • 手势只在 Feed 有效区域触发；列表滚动、弹层操作、文字选择和进度拖动不触发全局切歌。保留可访问的切歌和进度控制。
  • 快速连续切换以最后一次有效意图为准，旧媒体加载完成不能抢回播放；候选不足与暂时加载失败分开处理。
  • 产品规划：突出本次分发对应的主推荐者，并提供其他同曲推荐者入口。主推荐者来自具体推荐记录，不能用头像排列顺序猜测。
  • 产品规划：有明确语音来源时可听推荐理由，允许跳过或关闭；音量衔接、插入频率与后台视频转歌曲细节需要独立听感及设备验证。
  • MV 分期推进；Clips 根据素材覆盖、制作成本和授权评估，暂不默认启用。
06

FR03 · 播放会话、队列与返回

入口展示与来源结束 / 返回
Feed发现界面；发现队列按发现内容继续；无可播内容时提供恢复选择。
Library 的 Your recommendations当前点播界面；进入时的本人推荐顺序重播该列表或明确继续发现；浏览 Library 不改队列。
Saved songs / 个人歌单传统全屏播放器；对应收藏或歌单队列当前歌不因移出收藏立即中断；后续跳过已移除项。
主页推荐条目（规划）保留推荐者、附言及互动的 Feed 式内容页；当前人物推荐列表返回恢复主页和筛选位置；列表末端不自动接入发现队列。
底部播放栏封面与歌名打开当前播放详情；右侧为播放 / 暂停、播放列表所有共用页面保持一致；Feed 来源的详情落点仍需定稿。
  • 播放界面与播放来源分别管理。进入 Feed 式展示不等于切换为发现队列。
  • 歌曲、队列和推荐记录使用稳定标识。上一首、下一首、自然结束和邻歌预览采用同一来源顺序。
  • 浏览主页、评论、详情或左侧产品文档均不接管音频；明确点播才切换会话。暂停意图与进度不能因返回页面丢失。
  • 全屏播放器、歌单详情、Account 和个人主页使用统一进入 / 返回模式；底部栏复用同一组件，不把队列按钮替换成下一首或收藏。
  • 录音或试听附言属于有意音频接管，避免串录；结束后恢复原有播放意图，不把此前暂停的音乐强制播放。
07

FR04 / FR05 · 一键推荐与行为语义

动作用户含义独立边界
收藏以后还想听不自动推荐或关注。
推荐愿意让别人通过我发现这首歌无需附言、无需麦克风授权。
感谢（规划）这次推荐帮助了我必须归属到推荐记录，不代替收藏。
关注想继续探索这个人的品味不改变当前队列，不保证获得其全部内容。
  • 未推荐 → 点击一次 → 保存基础推荐 → 更新状态和数量。仅成功时播放头像飞入封面推荐位的动效；首次附加提示可以忽略。
  • 已推荐 → 再次点击 → 管理入口：补充 / 编辑附言，或二级确认撤销。不能将重复点击直接解释为撤销。
  • 一人一曲只有一条当前有效推荐；补充内容更新原记录而非新增计数。重复提交去重，保存失败回滚并保留编辑内容。
  • 撤销移除推荐及其附言，收藏独立保留；取消附言不取消基础推荐。已发生互动的历史归因按正式服务规则保留，不篡改历史事实。
  • 普通底部提示约 3 秒，含 Add a note 的操作提示约 6 秒，交互或焦点停留时暂停消失。头像动效约 760ms，减少动态效果时改为淡入。
08

FR06 · 语音与文字附言

  • 两种可选表达方式共用同一推荐记录。文字可直接进入输入框，录音只在主动点击后请求麦克风权限。
  • 文字上限 100 字符，输入框右下角显示已输入 / 上限；输入、粘贴、编辑和提交的计数规则一致，达到上限仍可删除修改。
  • 录音最长 60 秒，支持停止、试听、重录、取消和提交；录后可转为可编辑文字，转写失败可保留录音或手动输入。
  • 保存前不公开未提交内容。编辑回填已保存内容；更换录音必须在替换保存成功后才移除旧版本。
  • 权限拒绝、无设备、转写失败、存储失败分别给出恢复动作；基础推荐仍然有效。加载未完成或读取失败时不得覆盖原有附言。
  • 原型提供本机录制与保存体验；正式上传、审核、分发和跨设备同步属于产品规划。推荐已保存不等于其他人已经收到或听到。
09

FR08 / FR13 · 个人主页、推荐资产与关系

  • 个人主页沿用非洲版封面、头像、名字、身份信息、关注与原有内容模块，将推荐作为音乐资产融入；个人封面独立于推荐歌曲封面。
  • 本人使用实际显示名，当前为 Leesy；自己的历史记录仍归属同一账号。移除直播头像挂件和 Live 标记；Follow / Following 是同一按钮的互斥状态。
  • 推荐、评论、回复中的头像与名字都可以打开对应主页。返回恢复来源面板、滚动位置及未提交草稿，不重置播放。
  • 推荐模块默认最多预览 5 条，封面规格与 Playlists 统一，More 进入全屏列表；完整列表按每页 20 条承载，筛选和返回位置保留。
  • All / Voice / Words 分别展示全部与含对应附言的推荐；空分类不能显示为加载错误；本人可编辑，其他人只看允许公开的内容。
  • 产品规划：推荐条目首先承载推荐内容及其反馈，而不仅是回听歌曲。卡片可显示可归属的回复人数 / 未读；歌曲总推荐人数单列，两种统计不能混算。
  • 当前主页推荐仍使用点播界面；进入 Feed 式内容页和推荐反馈归因属于产品规划。
  • 分享须落到可访问的歌曲 / 推荐内容；私有本机附言不能被包装为已公开可分享。正式关注关系、隐私及分享链路需服务接入。
10

FR09 · 反馈、消息与回访

产品规划
  • 围绕用户自己的推荐及相关互动组织消息，一级为互动列表，私信会话为二级；无关官方消息不占据音乐反馈入口。
  • 反馈链必须完整：推荐者 → 推荐记录 → 互动者与行为 → 收件人 → 点开后的具体内容位置。
  • 回复人数按对该推荐作出回复的独立用户计数；未读回复按明确消息规则维护。歌曲层评论不自动归属到某个推荐者。
  • 歌曲总推荐人数按同曲有效推荐者去重计算，与本人推荐收到的回复独立展示。没有可靠数据时不编造数字。
  • 消息点击定位相应推荐或回复；已删除、已撤回、不可见或不可播时说明原因并保留返回路径。
  • 重复互动如何聚合、何时清除未读、私信权限和通知频次需定稿；送达、阅读与回访分别统计，红点数量不代表有效反馈。
  • 正式通知需允许用户管理提醒；空状态描述暂无互动，不评价用户的人气或品味。
11

FR10 / FR11 · Music、Library 与基础音乐能力

  • Music 提供 Feed 之外的主动探索出口。一期复用主题 / 场景列表、搜索与现有播放器；曲风入口、Radio 或自适应频道方案用实际内容比较后决定。
  • 搜索歌曲、艺人及可用歌单；无匹配与加载失败分开。不能用相似结果冒充精确命中，也不能用无效封面制造完整曲库印象。
  • 浏览歌单不中断当前音乐；点击歌曲或播放歌单后才切换为该列表的队列。歌单详情使用全屏页面及统一底部播放栏。
  • Library 承接 Saved songs、Your recommendations、个人歌单与最近播放；收藏、推荐、歌单成员分别保存，不能相互隐式删除。
  • 支持创建歌单、添加、去重、移除及空状态。历史来自实际歌曲播放，艺人介绍不能计为歌曲已听完。
  • 已收藏但不可播放的歌曲保留信息与原因，不静默删除用户资产。正式云同步、跨设备恢复与离线能力需要服务支持。
  • 产品规划：Library 承接关注艺人的 What’s new；内容来源、排序、已读及与消息的分工需定稿。

FR12 · 可见性、举报与屏蔽

产品规划
  • 公开推荐与私有收藏、历史分开定义。正式上线前明确可见范围、审核状态和本人 / 他人的展示差异，不默认公开全部听歌记录。
  • 举报与屏蔽是不同操作；举报有原因、取消、提交结果及处理路径，失败不能显示为已送达。
  • 屏蔽原则为减少接触该人的后续推荐与人声，不删除用户已收藏的歌曲；当前音乐、解除屏蔽和历史互动的细节须定稿。
  • 推荐 / 附言至少区分草稿、提交中、待审核、可见、未通过、撤回和失败；本人可定位问题，其他人不看到未授权内容。
  • 账号注销、数据删除与导出、权限撤回、媒体保留周期由正式隐私与服务方案定义，并提供实际可执行的流程。

FR14 · 广告、会员与下载权益

产品规划
身份方向尚需确认
普通用户按曲目权益提供基础在线听歌能力免费 / VIP 曲目覆盖、受限提示。
广告解锁用户完成广告后获得明确范围的在线收听权益解锁对象、时长、频次和到期行为。
付费会员按订阅方案提供会员权益价格、周期、恢复购买、下载及离线权限。
  • 下载采用再次观看广告或仅限付费，尚未定案；不得将两种方式同时当作既定规则。
  • 在观看广告或付款前说明将获得什么；广告完成回执与权益发放一致，提前关闭、失败和超时均可恢复。
  • 订阅取消、支付失败、权益过期、恢复购买和离线授权到期必须有清楚状态；不能显示虚假下载成功。
  • 赠送会员可作为验证方案，赠送天数及价格均未冻结；不照搬讨论中的竞品数字。

关键验收标准

路径通过条件
首次起播与切歌显示目标与实际媒体一致；允许及限制自动播放的场景均有可恢复体验；旧加载请求不能抢播。

浏览与返回主页、详情、评论及说明切换不改变当前播放；返回恢复入口与位置。
个人主页原有模块保留，推荐预览 5 条、More 分页；头像和名字通往正确用户；关注仅一组状态。
推荐反馈（规划）真实推荐归属正确；歌曲总量与个人回复独立；消息定位准确，失效目标可恢复。
权益（规划）先说明权益，成功后准确发放；失败不产生成功假象；到期 / 恢复可验证。
  • 验收记录区分：需求已定义、功能已实现、本地验证、上线验证、用户验收；不得把文档完备当成功能已交付。
